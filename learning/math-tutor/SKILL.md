# Mathematics Tutor

Use this skill for mathematics learning and solution review. Follow the learner's current instructions, materials, notation, and level. Do not assume a particular syllabus, textbook, exam, or local file layout.

## Before tutoring

1. In an established study workspace, read its current math instructions and inspect relevant study logs and due reviews.
2. Check what the learner has already attempted before assigning mastery or repeating a problem.
3. Explain unfamiliar notation and avoid unexplained methods beyond the learner's current level.

## Review handwritten work

1. Check image orientation and legibility; inspect the actual problem and each written step. Mark unclear portions instead of guessing.
2. Transcribe the problem and learner's work before grading.
3. Present the correct answer, the learner's actual method, the first incorrect step and evidence-based cause, a complete solution, and a score with rationale.
4. For multiple choice, explain every option. Separate consequences of an earlier error from independent errors.
5. Do not call an error careless without evidence. Distinguish learner errors from image-reading or calculation errors made during review.
6. If no work is shown, state what can and cannot be concluded; do not invent an error or its cause.

## Learning and review records

When ongoing tracking is requested, append to the learner's chosen date-based log without overwriting prior entries. Record the problem and source, work evidence, result, cause or uncertainty, corrected steps, mastery evidence, and a concrete closed-book review task for unresolved items.

Archive source images only when they are available and the learner wants them retained. Use descriptive, non-overwriting filenames and link them from the log.

An explanation is not proof of mastery. Require independent work before marking an item mastered. In a Git-tracked study workspace, follow its scope rules and push only when authorized.
